# Debug LOG

### ERRO: Handshake and infinite loop (Master <-> Crypto)

1) 
- Problem: `crypto_done` always  active. Hence, the `block_count` rised until 1300, lacked system in `FILL_BUFFER` and `EXEC_ENCRYPT`.
- Hypothesis: Crypt activated `crypto_done` in ENCRYPT and never deactivated. The master looked to the `FILL_BUFFER` and remained forever.
- Solution: Move the deactivation to the `DONE_CRYPT` or the Master clean (generating `crypto_ack`).

- Status: Solved

2)
- Problem: Attempt to drive input-only modport: `crypto_done`

- Hipothesis: Try to write in `spi_if.crypto_done` inside of Master. `crypto_done` is an input in modport. Hence, the Master only can read, never write.

- Solution: Create an acknowledge signal `crypto_ack` that master write and crypto read.

- Status: solved

3)
- Problem: Multidriven in `crypto_done`.

- Hipothesis: Trying to use inout to solve handshake. The crypto and Master was writing the same wire (`crypto_done`) in different blocks.

- Solution: Split in `crypto_done` (crypto -> master) and `crypto_ack` (master -> crypto).

- Status: solved

### ERRO: Interface, modport and illegal attributes

1)
- Problem: Attempt to drive input-only modport: `miso_encrypted`.

- Hipothesis: Trying to `spi_if.miso_encrypted <= sr_rx` in DONE state of Master. The `miso_encrypted` is generated by crypto (output in `crypto_f`) and read by master (input in `master_f`).

- Solution: Remove the line. The data received by master already exist in `sr_rx` or in `spi_if.miso_encrypted` (read not write).

- Status: Solved

2)
- Problem: WIDTHTRUNC: mosi = `spi_if.data_to_send`. 

- Hipothesis: Attributing 64 bits vector to the serial pin of 1 bit. Missing the serial pin `mosi` with parallel data `data_to_send`.

- Solution: change to the `assign mosi = spi_if.mosi`. (connecting pin of right signal to the interface).

- Status: solved

3) 
- Problem: MULTIDRIVEN in `ss_prev`.

- Hipothesis: Updating `ss_prev` in two different always_ff (posedge and negedge sck in slave). Knowing that a register `reg` only can be write by 1 unique block always.

- Solution: Keeping th attribution inside of posedge block and removing in negedge block.

- Status: solved

### ERRO: Key generation (LFSR) and clock

1)
- Problem: LFSR (`lfsr_m`) always zero.

- Hipothesis: `encrypted_text` was zero or equal to the `plain_text`. The xor with the key didn't changed the data. The LFSR doesn't initialized in reset (or overwritten). or `always_ff` sensitive to the `sck` (`posedge crypto_if.sck`), but SCK stopped during processing, lacking the 64 cycles updates.

- Solution: Initialize the seeds non-zero (64'h32...). Change always_ff from crypto to use `clk`, sampling the `sck` only with data.

- Status: Solved

2)
- Problem: 96 bits key bad extracted.

- Hipothesis: The SIMON built wrong values or random. The `lfsr_m[31:0]`, `lfsr_m[63:32]` and `lfsr_m[31:0]` in a wrong way with a separated ordem (LSB_first vs MSB_fist).

- Solution: Paddronizing extraction: `round_key[0] <= lfsr_m[31:0];`, `round_key[1] <= lfsr_m[63:32];` and `round_key[3] <= lfsr_m[31:0];` and ensure that Slave use the same.

- Status: Solved


### ERRO: SIMON algorithms
1)
- Problem: SIMON expansion key wrong.

- Hipothesis: subkeys incorrect generation. Using ~(NOT) and a rotation (ROR1) that don't exist in specification. Forgot the condition `if (i % 2 == 0)` to ROR4.

- Solution: `temp = ROR3(round_key[i-1])` if i even: `temp = temp ^ ROR4(round_key[i-1]);` `round_key[i] = round_key[i-2] ^ temp ^ Z[i-2]`

- Status: Solved

2)
- Problem: Blocking assignment '=' in sequential logic process. Suggest using delayed assignment '<='. e.g, round_key[i] = 32'h0;
Warning: Use "/*verilator lint_off BLKSEQ */" and lint_on around source to disable.
e.g, round_key[i] <= ~round_key[i-2] ^ temp ^ {{31{1'b0}}, Z[i-4]};

- Hipothesis: Using blocking (=) inside of always_ff to `round_key[i]` and non_blocking (<=) to the `temp`, generating wrong validation. 

- Solution: using a expansion to 42, such as round_key <= '{42{32'h0}}; instead of use a for loop in !reset condition, knowing that round_key is declared: logic [31:0] round_key [0:41]; that is vector of 32 bits with 42 words.
Using /*verilator lint_off BLKSEQ */ above and below of `round_key[i] <= ~round_key[i-2]...`.

- Status: Solved

3)
- Problem: Ciphertext didn't exposed. Which testbench read 0 forever.

- Hipothesis: `ciphertext` updated internally, but never attributed to the interface signal `spi_if.ciphertext`.

- Solution: Adding `crypto_if.ciphertext <= ciphertext` in final state of SIMON.

- Status: Solved

### ERRO: SIMON algorithms
1)
- Problem: Slave receive lack data. Which Slave display `0x0000050000000000` or `0x002fffffffffffff` instead of a complete ciphertext.

- Hipothesis: `ciphertext` updated internally, but never attributed to the interface signal `spi_if.ciphertext`. In master, `spi_if.ss <= 1` was executed in the same cycle which `bit_count` that achieved 63(last bit). The slaver when saw `ss` in edge, reseted the shifter register before catch 63 bits.

- Solution: delay `ss` edge in 1 cycle in the master, using `ss_delay`. In slave, use posedge `ss` (`ss && !ss_prev`) to reset, instead of reset when `ss` activated.

- Status: Solved

2)
- Problem: Copying criptographic formules without order verification of operations and specifications. The simon has: SIMON 64/128, SIMON 64/96, SIMON 128/128, SIMON 128/192, SIMON 128/256. 

- Hipothesis: Read specific rules and learn expansion keys and round functions.


### ERRO: FSM flux (encrypt X decrypt)
1)
- Problem: Executing decrypt after transmission.

- Hipothesis: Crypto encrypted, transmited to the slaver, and after that try decription inside of Crypto. The linear FSM: RECEPTION -> SIMON_ENCRYPT -> TRANSMISSION -> DECRYPT -> DONE. Wasn't separation between (WRITE) and (READ).

- Solution: Create 2 paths: if `is_write` go to the `SIMON_ENCRYPT`. Go to the `SIMON_DECRYPT`. Both go to the `TRANSMISSION` and after that to the `DONE_CRYPT`. The `DECRYPT` don't must be executed in WRITE.

- Status: Solved
